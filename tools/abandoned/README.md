# 已废弃的做法

这里的东西**不在任何流程里**，保留下来只是为了记住"哪条路走不通、为什么"，
避免以后有人（包括我自己）觉得"再调一版就好了"。

## mkexpr.py —— 局部表情编辑（给"眨眼"造差分帧）

思路：不重新生成整张图，只改眼部像素，其他像素逐位不变，这样帧间像素级对齐，
切帧时不会"跳一下"。里面花了很大力气做**眼窝回填**（把眼睛抹掉后填上自然的肤色）。

结论：**整条路都不成立，别再碰。**

两次失败：

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 | 矩形 mask + inpaint | 模型直接吐出灰块 / 黑条 / 蓝条（见归档 `04_美术素材/v1_初版/003_闭眼inpaint试验/`） |
| v2 / v3 | 抹平眼区 + 画一根眼睑弧线 | 睫毛、下眼睑、外眼角全部消失，只剩一根 1~2px 的细线；眼窝还有灰霾 |

**根因不是参数没调好**，而是：雪之下雪乃的上眼睑是一条**又粗又黑的睫毛线**，
带锥度（外眼角粗、内眼角细）并挑出外眼角。这种画法用程序合成画不出来，
用扩散模型局部重绘又会丢角色特征（这正是 v1/v2 整版失败的根因）。

眼窝回填那部分的算法细节是有效的、也花了功夫（`暖色肤色最近邻初值 +
局部小半径归一化卷积扩散`，三个必须同时满足的条件写在函数注释里），
如果以后要做**别的**眼部处理（比如贴高光、做眼神移动），可以拿来复用。
但"做一张闭眼差分"这件事，靠它解决不了。

真正可行的两条路（都需要项目外部的资源）：

1. **Live2D** —— 眼睛是独立图层，眨眼是图层变换，压根不需要"重绘"。
   代价：需要建模师把立绘拆件+绑骨。这是桌宠/VTuber 领域的工业标准做法。
2. **差分立绘** —— 请画师（或拿到官方/同人差分）画一张闭眼图，直接当第二帧用。
   代价：需要一张画；但一旦有了，接进代码只要十几行。

两条都不是"再调一版算法"能解决的，所以 v3 直接移除了眨眼功能，
情绪反馈改用叠加式 CSS 腮红（见 `renderer/pet.css` 的 `#blush`）。
